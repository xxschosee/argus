# Capability Map: Argus

Argus — сторож и авто-лечитель для Paper-серверов. Бесплатный, open source.

Каждая строка — модуль с собственным контрактом и собственным критерием готовности.
Модули нумеруются один раз и больше не переименовываются.

| Module id | Responsibility | Depends on |
|---|---|---|
| `metrics` | Съём и хранение метрик: MSPT, TPS (1/5/15 м), heap, игроки, сущности, чанки | — |
| `diagnosis` | Превращение снапшота метрик в диагнозы (причина + критичность + доказательства) | metrics |
| `healer` | План и применение лечебных действий по диагнозу | diagnosis, metrics |
| `hotspot` | Поиск виновника: инкрементальный скан чанков по бюджету тиков | metrics, diagnosis |
| `notify` | Отправка алертов в Telegram (Bot API) | diagnosis, healer |
| `panel` | Интеграция с Pterodactyl: статус сервера, рестарт по кнопке | notify, healer |
| `report` | Команды `/argus`: статус, история инцидентов, ручное лечение | metrics, diagnosis, healer, hotspot |

## Направление зависимостей

```
metrics ──► diagnosis ──► healer ──► notify ──► panel
   │            │                      ▲
   └────────────┴──────► hotspot ──────┘
                                      
report читает всё (только чтение, обратных стрелок нет)
```

Правила:
- Обратных стрелок нет. `metrics` ничего не знает про диагнозы.
- `healer` не знает про Telegram — он возвращает план действий, применение живёт в отдельном слое.
- `notify` не знает про Pterodactyl — панель подключается к `healer` через интерфейс исполнителя.
- Если два модуля нуждаются друг в друге — это один модуль.

## Порядок сборки

```
metrics → diagnosis → healer → hotspot → notify → panel → report
```

- `metrics` и `diagnosis` — фундамент, без них остальное нечем тестировать.
- `healer` — первая «польза»: плагин начинает чинить.
- `hotspot` — нужен, чтобы лечить прицельно, а не «выгрузить всё подряд».
- `notify` — превращает молчаливую лечебку в управляемую: админ видит, что произошло.
- `panel` — рестарт зависшего сервера, недостижимо изнутри процесса.
- `report` — обвязка для человека: команды и история.

## Границы MVP

В первую поставку входят `metrics`, `diagnosis`, `healer`, `hotspot`, `notify`.
`panel` и `report` — вторая итерация (см. `SPEC.md` → Not Doing).
