# Spec: Argus — сторож и авто-лечитель для Paper-серверов

> Status: draft v0.1 · 2026-10-20 · Автор: агент, ревью: владелец проекта
> Модульная карта: `CAPABILITY-MAP.md` · План: `tasks/plan.md` · Задачи: `tasks/todo.md`

## ДОПУЩЕНИЯ, КОТОРЫЕ Я ДЕЛАЮ (поправь или скажи «поехали»)

1. **Лицензия MIT.** Нужна для Modrinth: open-source без ограничений на монетизацию.
2. **Полностью бесплатно, без Pro-версии.** Монетизация — через хостинг и услуги, не через плагин.
3. **Ядро — Paper API `1.21.11-R0.1-SNAPSHOT`, Java 21, `api-version: '1.21'`.**
   Значит: ставится на 1.21.x и на все более новые сервера. Folia — не заявляем в v1.
4. **Group id `dev.argus`** — временно, поменяем на свой GitHub-орг перед публикацией.
5. **Telegram — через Bot API напрямую** (`sendMessage` + `getUpdates`), без aiogram/зависимостей.
   Отдельный бот-токен, не пересекается с вашими существующими ботами.
6. **Плагин НЕ рекламируется в 19 MC-чатах.** Дистрибуция: Modrinth, GitHub, свой Telegram-канал.
7. **Вердикт по античиту — отрицательный:** в вашей аудитории читы это фича анархии, не проблема.
   Модуля античита в проекте нет и не будет.
8. **v1 не трогает данные игроков** — только агрегаты сервера. Никаких логов, никакого ПДн.
9. **Лечение по умолчанию только в безопасном режиме** (снижение нагрузки, разгрузка чанков).
   Разрушительные действия (удаление сущностей, рестарт) — выключены по умолчанию.

## Objective

Сервер администратора Minecraft внезапно начинает лагать в 3 часа ночи. Админ узнаёт об этом
утром, от злых игроков. Или не узнаёт — и сервер «умирает» тихо, неделями.

**Argus — плагин, который в этот момент не пишет отчёт, а сам находит причину, снимает её
и сообщает в Telegram что сделал.**

Пользователь: администратор небольшого Paper-сервера (5–100 игроков), чаще всего подросток
или студент, с ограниченным временем и без DevOps-компетенций. Второй пользователь —
владелец платного хостинга, которому важно, чтобы его сервер «не лагал» (это его аргумент
при продаже).

Успех = админ ставит плагин, забывает про него, а Telegram-канал сам сообщает
«был лаг 19.4 → причина: 2 300 мобов в чанке 12,-8 → выгрузил чанк, TPS вернулся в 19.8».

### Ключевые требования (acceptance criteria верхнего уровня)

| # | Требование | Критерий проверки |
|---|---|---|
| R1 | Плагин снимает метрики без просадки TPS | Стоимость съёма < 0.1 мс/тик, измеряется бенчмарком |
| R2 | Плагин различает 5 причин деградации | 5 unit-тестов на `DiagnosisEngine`, каждый с граничным значением |
| R3 | Плагин сам применяет безопасное лечение | 5 unit-тестов на `HealEngine`: диагноз → ожидаемый набор действий |
| R4 | Сканирование виновника не лагает сам | Инкрементальный скан: бюджет ≤ N чанков за тик, есть тест на бюджет |
| R5 | Админ получает алерт в Telegram | Алерт содержит причину, доказательства и что именно сделано |
| R6 | Один алерт на инцидент, а не на каждый тик | Edge-triggered: второй алерт только после снятия и нового инцидента |
| R7 | Плагин ничего не ломает сам | Все лечебные действия обратимы или безопасны; разрушительные — выключены по умолчанию |
| R8 | Работает на 1.21.x и новее | `api-version: '1.21'`, сборка против 1.21.11 API |
| R9 | Бесплатно и без телеметрии | Нет внешних вызовов, кроме Telegram (и только если токен задан) |
| R10 | Можно выключить в один файл | `config.yml` → `enabled: false` → плагин молчит и ничего не делает |

## Tech Stack

| Слой | Технология | Версия | Почему |
|---|---|---|---|
| Язык | Java | 21 (LTS) | Требование Paper 1.21.x; 21 уже стоит у админов |
| API | `io.papermc.paper:paper-api` | `1.21.11-R0.1-SNAPSHOT` | Paper — минимум Bukkit + async chunk loading + Adventure |
| Сборка | Gradle (Kotlin DSL) | 9.1.0 | Gradle 8.8 не работает на Java 25; 9.1 — актуальный |
| Тесты | JUnit 5 | 5.11.4 | Без сервера: ядро чистое, Bukkit только в адаптерах |
| Telegram | `java.net.http.HttpClient` | JDK 21 | Ноль зависимостей, Bot API — обычный HTTPS |
| Конфиг | Bukkit `YamlConfiguration` | — | Стандарт, без внешних библиотек |
| Логи | `java.util.logging` (через Bukkit) | — | Стандарт плагинов |

**Запрещено:** Shadow/relocate, `paper-plugin.yml` (нужна совместимость с Bukkit-дериватами),
зависимости от aiogram/Telethon-подобных SDK, любые сетевые вызовы кроме Telegram.

## Code Style

Java 21, records для иммутабельных данных, `final` на полях, никаких `var` в полях,
`Optional` не используется (вместо него — nullable + `@Nullable`).

```java
package dev.argus.core;

import java.util.Locale;

/**
 * Пороги, при которых состояние сервера считается деградировавшим.
 * Значения приходят из config.yml и валидируются при загрузке.
 *
 * @param warnMspt          порог предупреждения по времени тика, мс
 * @param criticalMspt      критический порог по времени тика, мс
 * @param warnTps           порог предупреждения по TPS (ниже — плохо)
 * @param criticalTps       критический порог по TPS
 * @param warnHeapRatio     порог предупреждения по доле кучи, 0..1
 * @param criticalHeapRatio критический порог по доле кучи, 0..1
 * @param maxEntities       предел нормального числа загруженных сущностей
 * @param maxChunks         предел нормального числа загруженных чанков
 * @param samplesBeforeAlarm сколько подряд идущих снимков должно быть плохо,
 *                           прежде чем сработает тревога (защита от одиночных всплесков)
 */
public record Thresholds(
        double warnMspt,
        double criticalMspt,
        double warnTps,
        double criticalTps,
        double warnHeapRatio,
        double criticalHeapRatio,
        int maxEntities,
        int maxChunks,
        int samplesBeforeAlarm
) {
    public Thresholds {
        if (warnMspt <= 0 || criticalMspt <= warnMspt) {
            throw new IllegalArgumentException("MSPT: critical должен быть больше warn");
        }
        if (warnTps <= 0 || criticalTps <= 0 || criticalTps >= warnTps) {
            throw new IllegalArgumentException("TPS: critical должен быть меньше warn");
        }
        // Для кучи «хуже» = «больше», поэтому critical обязан быть ВЫШЕ warn.
        if (warnHeapRatio <= 0 || criticalHeapRatio <= 0 || criticalHeapRatio <= warnHeapRatio) {
            throw new IllegalArgumentException("heap ratio: critical должен быть больше warn");
        }
        if (maxEntities <= 0 || maxChunks <= 0) {
            throw new IllegalArgumentException("лимиты должны быть положительными");
        }
        if (samplesBeforeAlarm < 1) {
            throw new IllegalArgumentException("samplesBeforeAlarm должен быть >= 1");
        }
    }

    public static Thresholds defaults() {
        return new Thresholds(
                45.0, 70.0,
                17.0, 12.0,
                0.80, 0.92,
                3000, 4000,
                3
        );
    }
}
```

Соглашения:
- Имена методов — `camelCase`, геттеры record'ов — `xxx()`.
- Один публичный класс на файл, имя файла = имя класса.
- Комментарии объясняют «почему», а не «что».
- Никаких `System.out` — только `plugin.getLogger()`.
- Логи: `info` при старте, `warning` при деградации, `severe` при неустранимой ошибке.

## Testing Strategy

| Уровень | Что тестируем | Где | Фреймворк |
|---|---|---|---|
| Unit | `DiagnosisEngine`: 5 причин × 3 состояния (норма / warn / critical) + edge-trigger | `src/test/java/dev/argus/core/` | JUnit 5 |
| Unit | `HealEngine`: диагноз → набор действий, порядок, обратимость | `src/test/java/dev/argus/core/` | JUnit 5 |
| Unit | `Thresholds`: валидация некорректных значений | `src/test/java/dev/argus/core/` | JUnit 5 |
| Unit | `HotSpotScanner`: бюджет за проход, корректный top-N | `src/test/java/dev/argus/platform/` | JUnit 5 |
| Integration | Загрузка `config.yml` → `Thresholds` | ручной прогон на Paper | — |
| Manual | Реальный лаг → алерт в Telegram → лечение | на тестовом сервере с лаг-фермой | — |

Требования к покрытию: **модуль `core` — 100 % покрытия ветвей** (там вся логика),
`platform`/`notify` — покрытие не требуется, они проверяются ручным прогоном.
Порог: `./gradlew test` обязан проходить без падений, минимум 20 тест-кейсов.

Принцип: тест сначала (красный), потом реализация (зелёный). Тест без RED-фазы
не считается написанным.

## Boundaries

**Всегда:**
- Тесты зелёные перед коммитом
- Никаких зависимостей в рантайме (кроме Bukkit API)
- Никаких сетевых вызовов, кроме Telegram Bot API, и только при заданном токене
- Никаких записей данных игроков
- Логи без токенов и персональных данных
- Коммиты атомарные, сообщения в стиле Conventional Commits

**Сначала спросить:**
- Смена `api-version` или миграция на 26.x / Folia
- Добавление любой зависимости
- Изменение схемы `config.yml` (breaking)
- Публикация релиза в Modrinth
- Добавление телеметрии или сбора данных об игроках

**Никогда:**
- Не коммитить секреты (токен Telegram, ключи API)
- Не удалять и не отключать упавшие тесты
- Не добавлять `folia-supported: true`, пока Folia реально не проверена
- Не вызывать Bukkit API из асинхронных потоков
- Не делать блокирующий I/O на основном потоке

## Success Criteria

Модуль считается готовым, когда выполнено всё перечисленное:

**`metrics`**
- [ ] `MetricsSnapshot` собирается раз в N тиков и содержит MSPT, TPS 1/5/15, heap, игроков, сущности, чанки
- [ ] Стоимость съёма измерена и < 0.1 мс
- [ ] Есть unit-тест на корректность значений снапшота

**`diagnosis`**
- [ ] Каждая из 5 причин обнаруживается на граничных значениях
- [ ] Эскалация warn → critical работает
- [ ] Edge-trigger: при длительной деградации алерт один, а не 20 в минуту
- [ ] При восстановлении состояние сбрасывается, инцидент закрывается

**`healer`**
- [ ] Каждой причине соответствует свой набор действий
- [ ] Разрушительные действия выключены по умолчанию в `config.yml`
- [ ] Каждое действие описывает цель и обратимость

**`hotspot`**
- [ ] Скан идёт инкрементально, бюджет на тик ограничен конфигом
- [ ] Возвращает top-N чанков по числу сущностей
- [ ] Есть тест на соблюдение бюджета

**`notify`**
- [ ] Алерт уходит в Telegram и содержит причину, цифры и список действий
- [ ] При отсутствии токена плагин работает молча, без ошибок в логе
- [ ] Сетевые ошибки не роняют плагин, есть retry с backoff
- [ ] Сообщение корректно экранируется для HTML-формата Telegram

**Общее**
- [ ] `./gradlew build` проходит, JAR собирается
- [ ] Валидатор вёрстки плагина проходит без ошибок
- [ ] На тестовом сервере искусственный лаг вызывает лечение и алерт

## Not Doing (и почему)

- **Античит** — в целевой аудитории читы это фича анархии, а не проблема. Модуль не делаем.
- **Плагин не рекламируется в MC-чатах** — по решению владельца. Реклама в этих чатах
  вызывает негатив у живых пользователей («рекламная помойка»), и это же мы видели в данных.
- **Кнопки в Telegram (callback) в v1** — требуют чтения `getUpdates`, а значит бот должен
  принадлежать плагину. Отдельная итерация после `panel`.
- **Folia в v1** — требует отдельного API и тестирования. `SchedulerFacade` спроектирован
  так, чтобы добавление Folia было одним новым классом, а не переписыванием.
  Флаг `folia-supported` не ставим, пока не проверено.
- **Веб-дашборд** — плагин не должен становиться веб-сервисом. Всё, что нужно админу,
  уходит в Telegram.
- **Pro/платная версия** — плагин полностью бесплатный, навсегда.
- **Сбор статистики игроков** — только агрегаты сервера. Данные игроков не трогаем.
- **Поддержка 26.x на старте** — `api-version: '1.21'` покрывает и её; отдельная сборка
  под новый API появится, когда понадобится.
- **`reduce_entity_limit`** — в Paper API нет способа изменить лимит сущностей на чанк.
  Действие оставлено в перечислении, но честно сообщает, что не поддерживается.

   и первых баг-репортов. Кто это будет, и можно ли им ставить плагин на свои серверы
