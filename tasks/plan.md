## 2. Ключевые технические решения

### 2.1 Ядро без Bukkit
`dev.argus.core` не импортирует `org.bukkit.*` нигде. Проверено grep'ом и архитектурой
пакетов: всё, что можно проверить без сервера, живёт в `core` и покрыто тестами.
Следствие: 52 юнит-теста гоняются за секунды, без Paper-сервера.

### 2.2 Edge-trigger вместо «кричи на каждом тике»
`DiagnosisEngine` держит счётчик подряд идущих плохих замеров и флаг «эпизод открыт».
Тревога приходит один раз на эпизод; при восстановлении — отдельное сообщение.
Без этого плагин отправлял бы десятки сообщений в минуту.

### 2.3 Поиск виновника инкрементально
Подсчёт сущностей в чанке — дорогая операция. Скан идёт частями
(`hotspot.chunks_per_tick`, по умолчанию 40 чанков за тик) и доводится до конца
за несколько секунд. Диагноз приходит сразу, виновник — следом отдельным сообщением.

### 2.4 Разделение плана и исполнения
`HealEngine.plan()` возвращает список `HealAction` и ничего не выполняет.
Исполняет `HealExecutor`. Благодаря этому вся логика лечения проверяется тестом,
а сервер трогается только в одном месте.

### 2.5 Безопасные действия по умолчанию
`HealEngine.defaultPolicy()` содержит только обратимые действия
(`notify_only`, `trim_memory`). Разрушительные (`remove_entities`, `restart_server`)
в список по умолчанию не входят и включаются админом вручную.
Тест `defaultPolicyIsSafe` не даёт это сломать случайно.

### 2.6 Никаких зависимостей в рантайме
В JAR попадает только код плагина. Telegram — обычный HTTPS через
`java.net.http.HttpClient` из JDK. Никакого Shade, никакого gson.

### 2.7 Folia-совместимость заложена, но не заявлена
Paper API 1.21.11 содержит `getRegionScheduler()`, `getGlobalRegionScheduler()`,
`getAsyncScheduler()` и `Entity#getScheduler()`. `SchedulerFacade` уже имеет
форму Folia. Но `folia-supported: true` в `plugin.yml` **не стоит**, пока это
не проверено на реальном Folia-сервере. Валидатор предупреждает, если флаг появится.

### 2.8 Версии
`api-version: '1.21'` → плагин грузится на 1.21.x и на всех более новых серверах.
Собрано против `paper-api:1.21.11-R0.1-SNAPSHOT`, Java 21, Gradle 9.1.0.

## 3. Что оказалось не по плану (обнаружено при реализации)

| Ожидание | Реальность | Решение |
|---|---|---|
| `Bukkit.setAutoSave(boolean)` есть | В Paper API 1.21.11 метода нет | Перешли на `World#setAutoSave(boolean)` — гасим автосохранение по мирам |
| `Chunk#setMaxEntities` есть | Метода нет в API | Действие `reduce_entity_limit` помечено как неподдерживаемое и честно логируется |
| `Server#getRegionScheduler()` нет | Есть, Paper API его содержит | Folia-совместимость без рефлексии |
| Пороги кучи валидны | Валидация была перевёрнута, тесты это поймали | `criticalHeapRatio` должен быть **больше** `warn` — исправлено |

## 4. Риски и как с ними живём

| Риск | Вероятность | Последствие | Митигация |
|---|---|---|---|
| Ложная тревога: разовый всплеск TPS | Средняя | Админ получает лишнее сообщение | `samples_before_alarm` (по умолчанию 3 замера ≈ 15 с) |
| Плагин сам ухудшает лаг сканом | Низкая | Лаг усиливается | Жёсткий бюджет: 40 чанков за тик, скан только при инциденте |
| `System.gc()` вызывает паузу | Средняя | Кратковременный фриз | По умолчанию входит в план лечения, но только при реальном превышении порога; можно убрать из `heal_actions` |
| Telegram недоступен | Низкая | Админ не узнаёт об инциденте | Сетевые ошибки не роняют плагин, есть запись в лог; сообщения не теряются молча — инцидент виден в `/argus history` |
| Утечка токена в лог | Низкая | Компрометация бота | Токен не пишется в лог и не попадает в сообщения |
| Аккаунт владельца бота заблокирован за спам | — | Молчание | Плагин не рассылает рекламу; частота настраивается |

## 5. Порядок дальнейшей работы

```
panel (Pterodactyl)  ──►  уведомления с кнопками  ──►  публикация на Modrinth
     │                          │
     └────► report (дашборд) ──┘
```

1. **`panel`** — рестарт зависшего сервера изнутри процесса невозможен, нужен API панели.
   Зависит от доступа к панели, поэтому идёт после `notify`.
2. **Кнопки в Telegram** — сейчас только отправка текста. Кнопки требуют чтения
   `getUpdates`, а значит бот должен принадлежать плагину (свой токен).
3. **`report`** — веб-дашборд истории инцидентов. Полезно, но не критично: `/argus history` закрывает базовую потребность.
4. **Публикация** — README, GIF-превью, страница Modrinth, Discord-сервер.
